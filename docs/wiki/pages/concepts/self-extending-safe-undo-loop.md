# Self-extending safe-undo loop

## What is it?

righthand's **signature story**: the end-to-end loop where a user (or the agent
driving righthand) adds a new command, it is immediately usable, and it can be
removed again with zero residue — `new` (or `build`) → auto-discovered → run →
journaled → `rollback` → gone from `tools`. It is the product's central proof:
**self-extend, then safely undo.**

## Why does it matter?

This loop is the whole point of righthand as a self-recursive self-builder. It
shows that the three pillars compose into one coherent experience:

- **Self-extension** — righthand writes/scaffolds new commands into its own
  surface (C3 authoring + C5 self-builder) and they run without any wiring step.
- **Safety** — every mutation is journaled and versioned in an `isomorphic-git`
  store (C7), so any addition can be reverted.
- **Transparency** — `tools --json` reflects the live, auto-discovered surface,
  so an MCP-aware agent always sees the truth, including that a removed command
  is really gone.

Without all three, the story breaks: extension without discovery means the new
command doesn't run; discovery without journaling means an addition can't be
undone.

## Key rules / properties

- Adding a command = drop a file (scaffolded by `new`, or generated by `build`).
  There is **no shared-file edit** and **no registration step** — auto-discovery
  picks it up next run (see
  [command-auto-discovery-one-file-per-command-plugin-handlers-](./command-auto-discovery-one-file-per-command-plugin-handlers.md)).
- Every command mutation is journaled with a `change_id` before it is visible;
  `changes` lists them, `rollback --yes` reverts the latest (see
  [mutating-commands-own-their-journaling-not-a-dispatch-auto-w](./mutating-commands-own-their-journaling-not-a-dispatch-auto-w.md)).
- Rollback never touches app code — it only reverts righthand's own footprint
  (the [factory-reset-capability-c-reset](./factory-reset-capability-c-reset.md) store), so the user's repo stays
  intact.
- After rollback, the command disappears from `tools` — the loop is provably
  reversible.

## Source

- `src/commands/new.ts` — scaffolds a command (extension).
- `src/commands/build.ts` — LLM generates + smoke-tests + installs a command.
- `src/commands/changes.ts`, `src/commands/rollback.ts`, `src/commands/reset.ts`
  — the undo surface.
- `src/discover.ts` — auto-discovery (extension is wiring-free).
- Proven live in a fresh temp project: `init → new mycmd → tools (discovered) →
  run → changes (journaled) → rollback → tools (gone) → doctor (green)`.
