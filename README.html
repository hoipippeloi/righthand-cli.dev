README · feature summary

righthand

The coding agent's always-available operations right-hand.
TL;DR — A standalone CLI that any AI coding agent (Claude Code, Cursor, Copilot, Aider, pi…) shells out to per task to offload everything that isn't writing code: CI/CD, logs, docs, tasks, admin, web research. It returns a compressed, schema'd JSON result, keeping the agent's context window free for code. It can use an LLM itself and even write new commands into its own surface — safely, with full rollback.
Node 24 / Bun no build step ~115ms cold-start deps: citty + isomorphic-git 173 tests

How it works

Every call is a fresh subprocess: righthand loads config, discovers the command (reading manifest JSON only — no handler code), gates it through the capability sandbox and an approval gate, runs the handler (wrapping CLIs and/or calling its own LLM), compresses the result, journals any mutation, and emits one bounded envelope. Drag to pan, scroll to zoom, double-click to reset, ⛶ to fullscreen.

The dispatch path · three short-circuits (usage / capability-denied / needs_human) map to exit codes 2 / 6 / 3.

Operate it

Three ways in — the terminal, the web UI, or a direct agent call. Expand the quick-start tabs for each.

# clone, install, put `righthand` on PATH
git clone <repo> righthand.cli && cd righthand.cli
npm install
npm link

righthand              # list commands
righthand init         # create ./.righthand footprint
righthand doctor       # health + integration check
# every command returns one bounded envelope; JSON when piped
$ righthand ci status
{ "ok": true, "command": "ci", "summary": "main: 2 failed, 1 running",
  "result": { "runs": [...] }, "needs_human": null,
  "meta": { "duration_ms": 142, "change_id": null, "tokens_used": 0 } }

$ righthand hello --needs-human ; echo $?
{ "ok": false, ..., "needs_human": "..." }
3
# a visual runner — browse, fill a schema-generated form, run
$ righthand web
righthand web → http://127.0.0.1:8787/

# the UI drives the same in-process dispatch as the CLI,
# so config, capabilities, and rollback all apply.
# MCP-aware agents enumerate once, then dispatch
$ righthand tools --json
{ "tools": [ { "name": "ci", "description": "...", "inputSchema": {...} }, ... ] }

# the descriptors are MCP-shaped — any agent that speaks MCP
# can call righthand without being taught.

Configure

Layered config — project ./.righthand/config.json › user ~/.righthand/config.json › env (RIGHTHAND_*). A project .env is auto-loaded. Credentials use env:/keychain: indirection — never plaintext on disk, never in output.

// ./.righthand/config.json
{
  "providers": {
    "default": { "type": "openai-compatible",
                 "baseURL": "env:CHAT_BASE_URL",
                 "apiKey":  "env:DEEPSEEK_API_KEY",
                 "model":   "env:CHAT_MODEL" }
  },
  "permissions": { "allow": ["net:llm", "fs:write"], "deny": [] },
  "defaults": { "provider": "default" }
}
# .env at the project root — auto-loaded, never committed
DEEPSEEK_API_KEY=sk-...
CHAT_MODEL=deepseek-chat
CHAT_BASE_URL=https://api.deepseek.com/v1
★
Capabilities are deny-by-default. Strings exec: · net: · fs: · llm: (with * wildcards). Capability-gated commands (ci, llm, build, research…) are denied until you grant them in permissions.allow. Run righthand doctor to see what each command needs.

Enhance it

Four ways, zero shared-file edits — commands are auto-discovered. The contract is one module exporting a descriptor + a handler; the source must be strip-only TypeScript (no parameter properties, enums, or namespaces — Node/Bun run it with no build step).

// src/commands/greet.ts  — auto-discovered
import type { ToolDescriptor, CommandContext, Envelope } from "../contracts.ts";
import { makeEnvelope } from "../envelope.ts";

export const descriptor: ToolDescriptor = {
  name: "greet",
  description: "Greet a name",
  inputSchema: { type: "object",
    properties: { name: { type: "string" } }, additionalProperties: false },
  plugin: "@righthand/core", costTier: "free",
};

export async function run(ctx: CommandContext): Promise<Envelope> {
  return makeEnvelope({
    command: "greet",
    summary: `hi, ${ctx.args.name ?? "world"}!`,
    result: { name: ctx.args.name },
  });
}
# scaffold a starter (journaled → rollback-able)
righthand new mycmd --desc "does the thing"

# immediately discoverable + runnable
righthand mycmd
# the LLM writes + smoke-tests + installs a new command
righthand build "a command that prints the current git branch" --yes

# generate → validate → smoke-test → confirm → install
# journaled, so `righthand rollback` undoes it.
# a plugin is an npm package shipping a manifest.json fragment
righthand plugins install @acme/righthand-deploy

# { "plugin": "@acme/righthand-deploy",
#   "handler": "./handler.js",
#   "tools": [ { name, description, inputSchema, ... } ] }

When to use righthand best

  • An agent keeps stalling on ops — CI, deploys, logs, issues. Hand the task to righthand; get a one-line answer back.
  • Context bloat is hurting the agent's code work — let righthand do the noisy I/O and return only the summary.
  • You want one universal, agent-invokable ops surface instead of N MCP servers or raw gh/kubectl incantations.
  • You want to grow the tool with the agent — the self-builder writes new commands on demand, and rollback keeps it safe.
✕
And when not: righthand is a right-hand, not a coding agent — it doesn't edit your application source unless a command is explicitly scoped to. It shines for operational delegation.

FAQ

How does an agent actually call it?
It shells out: righthand <cmd> [args] --json. MCP-aware agents first read righthand tools --json for the descriptor list, then dispatch — no host registration or MCP server required.
Is anything the agent does permanent?
No. Every mutation is journaled as a before/after snapshot in an internal isomorphic-git store. righthand rollback undoes the last change (or N, or by id); righthand reset factory-resets a scope with an undo manifest. It never touches your application code.
Why deny-by-default capabilities?
righthand wraps real CLIs and calls real LLMs (which cost money and can exfiltrate). Each command declares what it needs (exec:gh, net:llm, …) and dispatch refuses to run it until you grant it. righthand doctor lists what's missing.
Does the web UI respect all that?
Yes — it runs commands through the same in-process dispatch as the CLI, so config, capabilities, rollback, and history all apply identically.
